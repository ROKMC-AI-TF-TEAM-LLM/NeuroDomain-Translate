# Phase 2 실행 기록 — 매칭 엔진

| 항목 | 내용 |
|---|---|
| 작성 | 2026-08-20 |
| 대상 | 계획서 v0.2 §6.3, §6.4, §7 |
| 선행 | [phase0-notes.md](phase0-notes.md) |

Phase 0 과 같은 성격의 문서다. **계획서와 다르게 구현한 부분과 그 이유**,
**계획서가 틀렸거나 성립하지 않는 부분**만 적는다.

> **선행 조건 미충족**: 계획서는 Phase 2 의 선행을 "Phase 1 (용어집 최소 200개)"
> 로 두었다. 현재 용어집은 Phase 0 샘플 20건이다. 200건은 엔진이 *유용*해지는
> 조건이지 *구축*되는 조건이 아니라고 보고 진행했다 — §11 의 수용 테스트 7건이
> 요구하는 용어(T-0142 / T-0300 / T-0301)가 샘플에 있고, Phase 1 의 용어집 교체는
> 엔진 코드를 바꾸지 않는다.

## 2. 두 개의 좌표계 — §6.3 을 그대로 구현하면 매칭이 깨진다

§6.3 은 두 가지를 동시에 요구한다.

1. ko2en 정규화는 공백을 전부 없앤다 — "합동 참모 본부" 를 잡기 위해
2. 경계 검증은 "앞이 한글이면 거부" — "기동군단" 안의 "군단" 을 막기 위해

**이 둘을 같은 공간에서 하면 충돌한다.** 공백을 없앤 뒤에는
`"제7기동군단 예하 각 군단은"` 이 `"제7기동군단예하각군단은"` 이 되고, 뒤쪽
`군단` 앞에 `각` 이 붙어 규칙 2에 걸린다. §11 의 수용 테스트
`("제7기동군단 예하 각 군단은", {"T-0301", "T-0300"})` 가 바로 이 사례이며,
계획서대로 짜면 T-0300 이 탈락한다.

**해결**: 스캔은 정규화 공간에서, **경계 검증과 결과 보고는 원문 좌표로 되돌린 뒤**
한다. `matcher.build_match_space()` 가 좌표 대응을 만들고, 이 함수와
`normalize_key` 가 항상 같은 결과를 내는지 테스트가 지킨다
(`test_match_space_agrees_with_normalize_key`). 둘이 갈라지면 인덱스에 등록한
표층형과 스캔 대상이 어긋나 매칭이 통째로 죽는다.

§6.3 에 이 구분을 명시할 것.

## 3. §7.5 를 지키려면 매칭된 표층형을 들고 다녀야 한다

§7.5 의 예시는 `합동참모본부 / 합참 → Joint Chiefs of Staff (JCS)` 다. 표제어와
**본문에 실제로 나타난 별칭**을 함께 보여준다.

처음에는 표제어만 넘겼는데, 본문에 `합참` 만 있으면 모델이 대응표의
`합동참모본부` 와 잇지 못해 대역어를 놓쳤다. mock 백엔드로도 재현됐고 검증
실패 → 재호출로 이어졌다.

**해결**: `TermMatch.surfaces` 에 실제 표층형을 담고, 대응표 표기를
`표제어 / 별칭` 으로 만든다 (`orchestrator._hint_source`).

## 4. `abbr_policy` 를 무시하면 프롬프트가 정책과 반대로 지시한다

`대령`(T-0087)은 `abbr_policy: always_full` 인데, ③ 전역 컨텍스트가
`First occurrence in this chunk (use full form + abbreviation): ... Colonel (COL)`
을 냈다. 실제 모델(A.X 4.0 Light) 출력은 `COL Kim Cheol-soo` 였다 —
**시킨 대로 한 것이다.**

원인은 두 곳이다.

- `_context_for` 가 `en_abbr` 이 있으면 정책과 무관하게 ③ 에 넣었다
- `_render_target` 이 `abbr` 이 있으면 무조건 `(약어)` 를 붙였다

**해결**: ③ 에는 `first_full_then_abbr` 인 용어만 넣고, `_apply_abbr_policy` 가
정책별로 표기를 정한다. `always_abbr` 은 약어 자체를 대역어로 쓴다.

영→한은 ③ 블록을 아예 쓰지 않는다. `en_abbr` 은 영어 쪽 약어이고 한국어
대역어는 약어 도입 관행이 다르다.

## 5. 다의어는 확정되면 좁혀야 한다 (§5.3)

§5.3 은 "매칭 단계에서 조건이 확정되면 하나로 좁히고, 확정되지 않으면 후보
전부를 조건과 함께" 라고 한다. 좁히는 쪽을 빠뜨리면 군종을 알면서도 모델에
선택을 맡기게 된다.

또 하나: **③ 과 ④ 가 같은 어휘를 써야 한다.** ③ 이
`Service branch: Republic of Korea Navy` 인데 ④ 가 `Captain (해군)` 이면 모델이
둘을 잇지 못한다. §7.5 의 예시는 `Captain (Navy)` 로 영문 표기를 쓴다.

**해결**: `analyze.resolve_branch()` 가 확정 시 대역어 하나로 좁히고,
`analyze.display_conditions()` 가 분기 값을 영문 표기로 바꾼다. 응답의
`terms_applied` 도 같은 값을 보고한다 (`_effective_targets`) — 프롬프트에서는
`Captain` 을 요구해 놓고 응답에 `Colonel` 이라고 적으면 프론트 하이라이트가
어긋난다.

### 실측 (A.X 4.0 Light)

| 입력 | 수정 전 | 수정 후 |
|---|---|---|
| 해군 김철수 **대령**은 … | `COL Kim Cheol-soo` ✗ | `Captain Kim Cheol-soo` ✓ |
| 육군 김철수 **대령**은 … | `Colonel Kim …` ✓ | `Colonel Kim …` ✓ |

## 6. 미등록 용어 후보 (R-04) — 세 가지 함정

§4.1 8단계와 §4.4 응답 예시(`{"type":"unknown_candidate","text":"천무-Ⅱ"}`)를
구현하면서 드러난 것들이다.

### 6-a. 일부만 겹치는 것은 변형이다

처음에는 기존 매칭과 한 글자라도 겹치면 후보에서 제외했다. 그러면 용어집에
`천무` 가 있을 때 `천무-Ⅱ` 가 묻힌다 — **정작 자기 항목이 필요한 것은 변형 쪽**
이고, §4.4 예시가 바로 그 사례다. **완전히** 덮인 것만 제외하도록 고쳤다.

### 6-b. Kiwi 는 하이픈에서 끊는다

`천무-Ⅱ` 의 NNP 는 `천무` 까지만이다. 변형 탐지용으로 구간을 넓히는
`variant_spans()` 를 따로 뒀다. `proper_noun_spans()` 는 매칭 교차검증이
구간을 정확히 비교하므로 손대지 않는다.

또 사전에 없는 고유명사는 NNP 로도 안 나온다 — `현무` 는 NNG 다. 정작 그런
것들이 미등록이라 약어 환각 위험이 가장 크다. 태그와 무관한 표층 패턴
(`한글 + -형식번호`)으로 보강했다.

> **정규식 함정**: 끝에 `\b` 를 붙이면 안 된다. 유니코드 로마 숫자(Ⅱ, U+2161)와
> 뒤따르는 조사(`도`, `가`)가 **둘 다 단어 문자**라 경계가 생기지 않아 매치가
> 통째로 실패한다. `_VARIANT_SUFFIX` 와 `_PERSON_TITLE_RE` 에서 같은 함정을 겪었다.

### 6-c. 사람 이름이 검수 대기열을 덮는다

`김철수 대령` 의 `김철수` 가 후보로 올라왔다. 보도자료마다 이름이 나오므로
(D-04) Phase 6 의 검수 대기열이 이름으로 뒤덮인다. 사람 이름은 용어집 항목이
아니고, 약어 환각의 대상도 아니다 — 프롬프트가 이미 로마자 표기를 지시한다(§7.2).

Kiwi 는 `김철수`(인명)와 `김포공항`(지명)을 똑같이 NNP 로 주고 NER API 도 없다.

**성씨 목록으로 거르지 않았다.** `정찰기`, `조종사`, `신호탄` 처럼 성씨 음절로
시작하는 실제 군사 용어가 대량으로 걸린다. 대신 **뒤따르는 계급·직함**을
신호로 쓴다 — 보도자료에서 인명은 거의 항상 계급과 함께 나온다.

## 7. 골든셋이 곧바로 매처 결함 두 건을 잡았다

`data/goldenset.jsonl` 의 각 항목에 `expect_terms`(그 문장에서 매칭되어야 할
term_id)를 달아 두고, 실제 매칭 결과와 대조하는 테스트를 붙였다
(`test_goldenset.py::test_expect_terms_match_the_engine`). 20건 중 2건이 어긋났고
**둘 다 매처 쪽이 틀린 것**이었다.

### 7-a. 조사 결합형이 빠져 있었다

`합동훈련이라고 합참이 설명했다` 에서 `합동훈련` 이 매칭되지 않았다.

경계 판정은 "조사 뒤에 한글이 더 오면 단어의 일부" 라는 규칙이다. 계획서 §6.3 의
`JOSA` 목록은 단일 조사만 담고 있어 `이` 를 조사로 보고, 그 뒤의 `라고` 를 보고
"더 긴 단어" 로 판단해 탈락시킨다. **`~이라고 밝혔다` 는 보도자료에서 가장 흔한
구문이다** (D-04).

인용 · 보조사 결합형(`이라고`, `이라며`, `에서는`, `으로부터` …)을 목록에 넣었다.
§6.3 의 `JOSA` 를 이 목록으로 갱신할 것.

> 목록이 22개에서 70개로 늘자 5,000자 처리가 250ms 로 뛰었다 — 후보마다 70회
> 문자열 비교를 돌기 때문이다. 정규식 한 번으로 바꿨다.
> **가장 긴 조사 하나만 확인하면 충분하다**: 그보다 짧은 조사를 택하면 그 뒤에는
> 반드시 한글(긴 조사의 나머지)이 오므로 어차피 걸러진다.

### 7-b. 영어 복수형을 못 잡았다

`Three brigades and one division` 에서 `division`(단수)은 잡고
`brigades`(복수)는 놓쳤다. 용어집은 단수형(`Brigade`)만 갖고 있고, 경계 검증이
뒤따르는 `s` 를 영숫자로 보고 거부한다.

복수 어미(`s` / `es`)만 붙은 경우를 허용하도록 고쳤다. `corpse` 안의 `corps` 는
뒤가 `e` 라 여전히 거부된다 (§11 수용 테스트).

## 8. 성능: 같은 텍스트를 Kiwi 로 두 번 분석하고 있었다

§11 의 200ms 기준을 재보니 약 230ms 였다. 구간별로 나눠 보니 원인이 분명했다.

| 구간 | 5,000자 기준 |
|---|---|
| `automaton.scan` (실제 매칭) | 2.0ms |
| `proper_noun_spans` (Kiwi 토큰화) | 95.9ms |
| `variant_spans` (**같은 텍스트를 또 토큰화**) | 76.4ms |
| TM 검색 ×7 청크 | 42.8ms |
| resolve + aggregate + 후보 수집 | 4.1ms |

토큰화를 한 번만 하도록 `KoreanAnalyzer.span_sets()` 로 합쳐 **141ms** 가 됐다.

**매칭 자체는 2ms 다.** 비용은 전부 형태소 분석에 있다. 용어집이 20건에서
3,000건으로 늘어도 Aho-Corasick 은 텍스트 길이에만 비례하므로(§6.3) 이 그림은
크게 바뀌지 않는다.

### 남은 성능 관심사

- **문장 분할이 별도로 90ms 를 더 쓴다.** `split_into_sents` 가 또 한 번
  토큰화하기 때문이다. 요청 전체로는 약 230ms 다. 세 번의 Kiwi 패스를 하나로
  합칠 여지가 있으나 §6.2 와 §6.3 을 결합해야 해서 미뤘다 — 필요하면 Phase 4
  (처리량)에서 다룬다.
- **TM 검색이 15건 코퍼스에 42.8ms 다.** Phase 1 의 목표는 10,000쌍 이상이다.
  `BM25Okapi.get_scores` 는 매 청크마다 전체 코퍼스를 훑으므로 이 비용이 어떻게
  늘어나는지 실데이터로 확인해야 한다. 지금 튜닝할 근거가 없어 남겨 둔다.
- 성능 테스트는 **중앙값 5회**로 잰다. 1회 측정은 실행 환경 변동으로 흔들린다.

## 9. 사고 기록 — 원문이 비면 모델이 문서를 지어낸다

**증상.** 영→한에 `"string"` 한 단어(Swagger UI 기본값)를 넣었더니 2027년 국방
예산안 보도자료가 통째로 나왔다. 총 50조 원, 전년 대비 5%, "김철수 중장" 의
발언까지 포함된 270자짜리 문서였다. **응답의 `warnings` 는 비어 있었다.**

**원인.** 출력이 `2026년 8월 19일` 로 시작했는데, 그것은 스타일 프리셋
(`prompts/styles/press_release.yaml`)에 적어 둔 날짜 예시다. 이름도 프리셋의
`김OO 대령` 패턴을 따랐다. 즉 **원문에 내용이 없자 모델이 시스템 프롬프트의
문체 예시를 내용으로 가져다 썼다.**

§7.2 의 `Do not add information not present in the source` 만으로는 막히지
않았다. 문체 예시는 형식을 보여주려고 넣은 것인데, 채울 내용이 없으면 그것이
내용이 된다.

**왜 심각한가.** 형식이 완벽해서 검수자가 놓치기 쉽다. 다수가 쓰는 환경(D-07)
에서 지어낸 국방 문서가 그럴듯하게 나오는 것은 오역보다 위험하다. 그런데
시스템은 아무것도 알아채지 못했다.

### 조치 1 — 프롬프트 (모델 의존)

양방향 템플릿의 핵심 지시에 두 줄을 넣었다.

```
- Translate ONLY what is given. If the source is a single word, a fragment,
  or has no clear meaning, render just that word or fragment. Never expand
  it into a sentence or a document.
- Never invent names, ranks, dates, figures, quotations, or organizations.
  The style guidance below shows FORMAT ONLY — never copy its example
  values into your output.
```

### 조치 2 — 탐지 (모델 무관)

프롬프트는 모델과 입력에 따라 뚫린다. `verify.py` 에 두 가지 검사를 넣고
`warnings` 로 노출한다 (§4.4).

| 검사 | 신호 | 잡는 것 |
|---|---|---|
| `check_length` | 출력/원문 글자 수 비율 | 부풀기(환각), 줄어들기(누락, R-09) |
| `check_language` | 출력에 타깃 언어 문자가 있는가 | 번역 대신 메타 코멘트를 낸 경우 |

임계값은 **넉넉히** 잡았다. 관측된 환각은 45~50배였고 정상 번역은 한→영
2.8배다. 조이면 정상 번역이 경고로 덮이고, 그러면 사용자가 경고 자체를 무시하게
된다. 골든셋이 실제 문장으로 채워지면(Phase 3) 분포를 보고 다시 잡을 것.

**재호출하지 않는다.** 환각에 재호출을 걸면 또 다른 환각이 나올 뿐이고 지연만
늘어난다. §6.5 의 "2차 위반은 warnings 로 전환, 사용자 판단" 과 같은 취급이다.

### 조치 후 (A.X 4.0 Light 실측)

| 입력 | 출력 | 경고 |
|---|---|---|
| `string` | `주어진 텍스트를 번역합니다.` (15자) | 없음 |
| `테스트` | 지어낸 문서 (174자) | `length_anomaly` |
| `...` | `(Translation provided in Korean …)` (61자) | `length_anomaly`, `wrong_language` |
| 정상 3건 | 정상 | 없음 (오탐 0) |

**남은 것.** 짧은 메타 응답(`주어진 텍스트를 번역합니다.`, 15자)은 두 검사를
모두 빠져나간다. 길이 하한 40자와 언어 검사 하한 20자 아래이기 때문이다.
위험도는 크게 낮아졌다 — 지어낸 수치도 이름도 없고, 사용자가 보면 번역이
아님을 안다. 임계값을 더 내리면 `K2 → K2 흑표` 같은 정상 사례가 걸리므로
그대로 둔다.

> ⚠ **이 경고들은 아직 사용자에게 보이지 않는다.** API 는 `warnings` 를
> 반환하지만 프론트에 표시 위치가 없다 (§4.4 가 예견한 상황). 지금은 로그와
> API 응답에만 남는다. 프론트에 경고 표시를 붙이는 것이 이 조치를 완성한다.

## 10. `kss` 제거의 파급 (D-22)

Phase 0 에서 결정한 대로 문장 분할을 `Kiwi.split_into_sents()` 로 바꿨다.
Phase 2 에서 확인된 부수 효과가 하나 있다: **분할기와 매칭이 같은 사용자 사전을
본다.** 용어집 표제어가 NNP 하나로 끊기므로, 문장 분할이 부대명 중간에서
끊지 않고 형태소 교차검증(§6.3)도 같은 사전 위에서 돈다. `kss` 를 썼다면 두
사전이 따로 놀았을 자리다.

## 12. 남은 것

### 이번 단계에서 하지 않은 것

- **TM 과 골든셋은 합성 샘플이다** (TM 15쌍, 골든셋 20건). 코드 경로를 배선
  확인하고 eval 을 만들 수 있게 하는 최소 데이터이며, `quality: "sample"` 로
  표시했다. 테스트가 `verified` 로 둔갑하는 것을 막는다
  (`test_repo_goldenset_is_all_sample`, `test_repo_tm_is_all_sample_quality`).
  Phase 1 · 3 에서 실제 데이터로 교체한다 (목표: TM 10,000쌍, 골든셋 50건).
  **이 샘플로 낸 chrF / COMET 은 품질 지표가 아니다.**
- **TM 과 골든셋은 문장이 겹치지 않아야 한다.** TM 은 few-shot 으로 프롬프트에
  들어가므로(§7.6), 골든셋 문장이 TM 에 있으면 모델이 정답을 보고 답하는 셈이다.
  `test_goldenset_and_tm_do_not_overlap` 이 검사한다. Phase 1 에서 실제 TM 을
  만들 때도 이 분리를 지킬 것.
- BM25 점수는 상한이 없어 그대로 임계값과 비교할 수 없다 — 최고 점수로 나눠
  정규화한 뒤 `TM_MIN_SCORE` 와 견준다. 실데이터가 들어오면 이 기준을 재조정할 것.
- **군종 LLM 폴백은 기본 비활성이다** (`NDT_SERVICE_CLASSIFY_LLM=false`).
  요청당 모델 호출이 하나 늘어나므로 O-04(동시 접속자 수) 확정 후 켠다.
  꺼져 있어도 다의어는 후보를 조건과 함께 넘긴다.
- **겹침 해소는 여전히 그리디다** (§6.3 의 알려진 한계). `[0,5]` 와 `[3,20]` 이
  경합하면 짧은 앞쪽을 택한다. 실무에서 확인되면 DP 로 교체한다.
